概念地图：三层五图法

先让概念在现实中可见，再拆开它的组成与运作，最后把它放回更大的系统，理解它为什么存在。

30 秒结论

理解概念不是背定义，而是建立一个可以观察、拆解、运行、定位和解释成因的心智模型。

看见它：现实中什么样 运行它：怎么用 + 怎么工作 放回世界：在哪 + 为什么存在

三层五图总览图

中心是概念，三层分别回答外显、内部、外部问题。

五图卡片

每张卡片都有独立小图，不能只写文字。

Visible Layer

外显图

现实中它长什么样，最小可观察场景是什么。

回答
别人如何观察到它？
误区
一上来堆定义。
Internal Layer A

结构图

它由哪些部分组成，边界在哪里，哪些是外部依赖。

回答
核心组件如何排列？
误区
把例子当本体。
Internal Layer B

动态机制图

“怎么用的”核心：如何调用它，以及它内部如何把输入变成输出。

回答
怎么跑起来？
误区
只写什么时候用。
External Layer A

位置图

它在更大体系中的层级、相邻概念和解决的问题层。

回答
它属于哪个系统？
误区
孤立解释概念。
External Layer B

环境动力图

它为什么出现，被什么推动，又反过来改变了什么。

回答
外部张力是什么？
误区
画成内部流程。

两种“动态”必须分开

一个讲内部工作，一个讲外部成因。

动态机制图

概念内部如何工作

关注使用方式和运作机制：人/系统如何调用它，关键组件如何协作，输入如何变成输出，如何反馈、验证、修正。

  • 输入 → 处理 → 输出
  • 组件交互
  • 反馈闭环

环境动力图

概念为什么存在

关注外部环境：什么需求、技术、成本、风险或历史条件推动它出现，它解决了什么张力，又推动了什么系统变化。

  • 外部驱动力
  • 矛盾 / 张力
  • 系统影响

示例带

每个概念用三层压缩，不展开成长文。

vibe coding

外显

人用自然语言提需求，AI 改代码、跑命令、产出功能。

内部

LLM、上下文、工具、测试、反馈循环共同构成工作流。

外部

LLM 代码能力提升与开发成本压力共同推动范式出现。

存在主义

外显

人面对选择，没有外部说明书替他决定。

内部

无预设意义 → 自由 → 选择 → 行动 → 责任。

外部

现代性危机和意义秩序崩塌，推动人重新追问如何活。

使用 Checklist

解释任何概念前先过一遍。

  • 有没有先画出现实里的“什么样”？
  • 结构图是否说明组成、边界和外部依赖？
  • 动态机制图是否解释怎么用、怎么工作？
  • 有没有避免把“怎么用”降级成“什么时候用”？
  • 位置图是否说明它在更大系统哪一层？
  • 环境动力图是否说明成因、张力和影响？
  • 是否区分内部动态和外部动力？
  • 最后能否压缩成一句可复述的心智模型？
